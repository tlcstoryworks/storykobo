# storykōbō community model

## Membership

storykōbō is intended to be an **18+ community**.

The platform should be designed around adult community participation from the beginning rather than attempting to retrofit an adult-only environment onto a general-audience system.

## Multiple affiliations

A user may belong to many groups at the same time.

For example, one person might be:

- a member
- a supporter
- part of an event team
- interested in cozy fantasy
- interested in worldbuilding
- part of a regional group

These are not mutually exclusive states.

## Group types

The eventual group system may distinguish between different kinds of membership, such as:

### Interest groups

Examples:

- genres
- creative disciplines
- hobbies
- topics

### Context groups

Examples:

- region
- age range

These may require stronger privacy controls and should never be assumed to be public.

### Event groups

Examples:

- annual event teams
- temporary challenge groups
- collaborative projects

### Community/status groups

Examples:

- supporters
- staff
- moderators

Permission-bearing status should still be represented through roles where appropriate rather than relying on group membership alone.

## Discovery

Groups may eventually provide ways to discover:

- members
- projects
- discussions
- events
- resources

Discovery should not require users to expose information they have chosen to keep private.

## Community interaction

The platform should support several levels of participation:

- quietly browsing
- following projects or people
- participating in discussions
- sharing creative work
- joining groups
- joining events
- encouraging other members
- contributing financially, if desired

No single participation style should be treated as the "correct" way to use the community.
